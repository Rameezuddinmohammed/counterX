# Lint-config root-cause fix and merchant-console type-safety cleanup (v1)

Two safe, behavior-preserving slices of a codebase sanity pass. The first traces the 963-error lint explosion to eslint linting the git-ignored `apps/landing/out` Next.js static export (minified JS producing 541 `no-undef` plus ~350 base-rule errors) and fixes it at the source by adding `**/out/**` to the flat-config ignores, then layers in a handful of genuine source fixes (a `renderCellValue` helper in the shared `DataTable`, three empty-interface-to-type-alias conversions, a stale `eslint-disable` removal, and a misleading union type collapsed to `string`). The second replaces `(item: any)` cell callbacks across the four merchant-console table pages with real row types, bridging to `DataTable`'s `Record<string, unknown>` constraint via `as unknown as` double-casts, and registers `eslint-plugin-react-hooks` scoped to that app so a pre-existing `exhaustive-deps` disable directive resolves. Net effect: lint drops from 963 errors to 1 (a deliberately-deferred `no-unsafe-return` in a worker test), with build, tests, and depcruise unaffected.

Watch for: the `as unknown as DataTableColumn<Record<string, unknown>>[]` double-cast at each table call site (confirmed) is the one spot where the type improvement is cosmetic at the boundary — the cells are now type-checked, but the `DataTable` generic still sees `Record<string, unknown>`, so the constraint itself is escaped rather than satisfied.

**Verdict**: APPROVED

## High-level view

The lint reduction is honest. The bulk of the 963 errors came from eslint walking an untracked build-output directory; ignoring `**/out/**` (alongside the already-ignored `**/dist/**`, `**/.next/**`, `**/build/**`) does not suppress any real source finding. The `caughtErrorsIgnorePattern: "^_"` addition and the stale `eslint-disable no-console` removal are config-and-cleanup, not blanket rule disabling. The single remaining error is left as declared backlog.

The `DataTable` `renderCellValue` helper changes rendering only for the previously-broken case. Primitives and null/undefined render exactly as before (`String(value)` and `""`); the only behavioral change is that objects/arrays now JSON-serialize instead of rendering `"[object Object]"`. No current caller relies on a column without a custom `cell` renderer over object data, so this is latent-bug prevention rather than a visible change.

The merchant-console typing is a real improvement inside each cell callback — `item` is now `Transaction`/`AuditEntry`/`Finding`/`MappingEntry` instead of `any` — but the fix stops at the `DataTable` boundary, where a double-cast re-erases the type. This is an acceptable bridge given that TS interfaces lack the implicit index signature `Record<string, unknown>` requires, but the constraint is escaped, not met.

The `useApi` `refetch` change is behavior-preserving: the return type was already `() => void`, and wrapping the async `fetchData` in a void-returning `useCallback` clears `no-misused-promises` at the one call site without altering when or how the refetch fires. The `OrderedStep.status` change from `"completed" | "declined" | string` to `string` is a no-op at the type level (the union already widened to `string`) and touches no runtime comparison.

<summary>Details</summary>

### Lint blowup was environmental, not source rot

The 963-error count was almost entirely eslint linting `apps/landing/out` — the untracked, git-ignored Next.js static export, which is minified JS that trips `no-undef` (541) and base rules (~350). The flat config already ignored `**/dist/**`, `**/.next/**`, `**/build/**`, and `**/coverage/**`; `out` was simply missing from that list. Adding `**/out/**` removes the noise without touching a single real source finding.

The `caughtErrorsIgnorePattern: "^_"` addition to `no-unused-vars` fixes an unused catch binding through config rather than editing source, matching the existing `argsIgnorePattern`/`varsIgnorePattern` convention. The removed `/* eslint-disable no-console */` / `/* eslint-enable no-console */` pair in the worker secret-leakage test wrapped code that reassigns `console` methods via `(console as unknown as Record<string, unknown>)[m]` — that bracketed member assignment does not trip `no-console`, so the directive was stale and its removal is inert.

### renderCellValue preserves primitive rendering

The prior default branch was `String(item[column.key] ?? "")`. For every primitive path the new helper is identical: strings pass through, numbers/booleans/bigints go through `String(...)`, and null/undefined become `""`. The behavioral delta is confined to the object/array/symbol/function branch, which previously produced `"[object Object]"` and now JSON-serializes with a try/catch fallback to `""` for circular or non-serializable values. Because every merchant-console column supplies a custom `cell` renderer, the default branch is not exercised by current callers, so this is defensive hardening rather than a visible change.

```
column.cell ? column.cell(item) : renderCellValue(item[column.key])
                                    │
          ┌─────────────────────────┴──────────────────────────┐
       primitives / null → identical to old String(x ?? "")   objects → JSON.stringify (was "[object Object]")
```

### Merchant-console typing stops at the DataTable boundary

Inside each column, `cell: (item: any)` became `cell: (item: Transaction)` (and `AuditEntry`/`Finding`/`MappingEntry`), so `item.amount.toLocaleString()`, `item.action.replace(...)`, and the `getXVariant(item.field)` calls are now checked against the actual row shape. The cost is the double-cast where the typed `columns`/`data` are handed to `DataTable`, whose generic requires `T extends Record<string, unknown>`. TS interfaces carry no implicit index signature, so `Transaction` is not assignable to `Record<string, unknown>`, forcing `as unknown as ...`. The type safety that matters — inside the callbacks, where the field access happens — is preserved, and the erasure is localized to the hand-off. The cleaner long-term fix is to loosen the `DataTable` constraint to `T extends object` or give the row types index signatures; left as backlog.

### Verification

Reproduced from the working tree: `pnpm lint` → 1 error (`@typescript-eslint/no-unsafe-return` at `apps/worker/src/secret-leakage.integration.test.ts:326`, the declared backlog item), no warnings — confirming the newly-registered `react-hooks` recommended rules surface no hidden `exhaustive-deps` findings in merchant-console. `pnpm build` → exit 0 across all workspaces. `pnpm depcruise` → 0 violations (1848 modules). The empty-interface-to-type-alias conversions in `input.tsx`/`loading.tsx`/`sidebar.tsx` add no members and compile clean.

Not tested: the `renderCellValue` object/array serialization branch and its try/catch fallback have no dedicated unit test in `packages/ui`; the path is currently unreached by callers but the behavior is unverified.
